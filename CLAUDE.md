# Simple Gmail — project notes for Claude

Chrome/Chromium MV3 extension that restyles Gmail into a calm, centred inbox.
No build step: load the folder unpacked. See README.md for features and install.

## Files

- `content.css` — all visual changes, every rule scoped to `html.sg-on` (master switch). Selector glossary at the top.
- `content.js` — settings → classes on `<html>`, plus things CSS can't do: date-group labels, slide-over menu clicks, floating compose, search/toolbar measuring.
- `springs.css` — GENERATED by `scripts/generate-springs.mjs` from Motion (motion.dev) springs. Edit the script, then `npm install && npm run springs`. Never hand-edit.
- `popup.*` — settings UI. `DEFAULTS` exists in both `content.js` and `popup.js`; keep them in sync.
- `background.js` — `Alt+Shift+S` toggles `enabled`.

## Gmail DOM facts (verified live in Oct 2026 — don't re-guess these)

Gmail's classes are obfuscated; many earlier guesses were wrong. These were confirmed by inspecting the real page:

- **Folder/label sidebar is `.aqn`** (the one containing links; a second, empty `.aqn` also exists → `.aqn:has(a)`).
- **`.aeN` is the narrow Mail/Chat/Meet app rail**, NOT the folder sidebar. Hidden under "hide side panels".
- **Compose button: `.T-I.T-I-KE.L3`** — it has no `gh="cm"` (older Gmail did; both are in `COMPOSE_SELECTOR`). It responds to mousedown/mouseup/click, not plain `.click()`. It lives inside `.aqn`.
- **Email list is not a real table**: `tbody` is `display:block`, each `tr.zA` is `display:flex` with ~10px top/bottom padding, and the cells are flex items (~20–26px tall). So paint row highlights on `tr.zA` itself (radius works there), never on the `td`s.
- **Row extra spacing** = transparent `border-top/bottom` on every `td` (`--sg-row-space`). Padding/fixed heights misalign Gmail's top-pinned sender/date/hover-buttons from the subject — don't use them.
- **Keyboard-focused row (j/k) has class `btb`**; the blue focus bar is `td.PF::before` (3px). Selected row: `.x7`. Read/unread: `.yO` / `.zE`. Date cell: `td.xW span[title]` (title = full timestamp).
- **Search bar `header form[role="search"]`** grows to ~360px tall when focused (suggestions are inside it). Never derive layout from its height while focused.
- **Search options panel is page-level `.ZF-Av > .SK`**, positioned by Gmail from its *default* header layout, not from the bar. It gets `--sg-search-x` / `--sg-search-w` from `placeSearch()`.
- Toolbar: `.G-atb`. Thread layout: `table.Bs`. Thread URLs end in a long id (`#inbox/FMfcg…`).
- Some header items are matched by English `aria-label` (Main menu, Support, Advanced search options).

## Design decisions (and why)

- **Search bar stays in Gmail's header flow**, centred via a measured `margin-left` (`--sg-search-left`). `position:fixed` made Gmail's panels open in the wrong place; `margin:auto` made it slide as the header's right side loaded late.
- **Toolbar width is measured** (`alignToolbar`) to match the list (`div[role=main]`) or the open mail card — a CSS max-width made it shrink-wrap and bunch up.
- **Slide-over menu is always rendered, parked with `transform`**; toggling `display` re-laid out the whole folder list on each open (laggy).
- **Scans run in `requestAnimationFrame`** (before paint) to avoid Gmail's unstyled layout flashing. The MutationObserver ignores changes inside `tr.zA`, the search form and `.ZF-Av` — rescanning on those caused hover stutter and delayed search suggestions.
- **Date headings are a `data-sg-group` attribute on the group's first `tr.zA`**, drawn by an absolutely positioned `::before` in a `margin-top` gap. NEVER insert rows into Gmail's `tbody`: Gmail maps a clicked row to a conversation by position, so inserted `tr.sg-group-row` rows made clicks open the conversation below (Oct 2026). Putting labels in the flow of a row's cells broke alignment.
- **Dark mode = root `filter: invert(1) contrast(.84) hue-rotate(180deg)`**, media gets the exact reverse in reverse order. Disabled when Gmail's own theme is dark (`.sg-gmail-dark`, detected from text colour). Saturated colours still lose some saturation — inherent to the approach.
- Theme colours come from CSS vars; `.sg-gmail-dark` swaps them to match Gmail's dark themes.
- Defaults the user chose: toolbar always visible, checkbox/star always visible, drag-handle dots kept, Normal width 1200px, Comfy rows.

## Debugging against real Gmail

- Ask before inspecting the user's Gmail; read structure only (classes, sizes, colours), never email content.
- The user browses in **Dia**. Dia runs page JS via AppleScript only when launched with `--enable-applescript-javascript` (`osascript -e 'quit app "Dia"'; open -a Dia --args --enable-applescript-javascript` — ask first, it restarts their browser). Then `tell application "Dia" to execute (active tab of window 1) javascript "…"`.
- Background tabs pause `requestAnimationFrame` and CSS transitions: extension scans and animated values won't update there. Measure with `transition:none`, or bring the tab forward.
- To test CSS changes before the user reloads, inject `springs.css + content.css` as a temporary `<style>` in the page, measure, then remove it. The page may still have the *old* extension CSS loaded — neutralise conflicting old rules in the test.
- Gmail opens search suggestions only on a real (trusted) click, not on `input.focus()`.
